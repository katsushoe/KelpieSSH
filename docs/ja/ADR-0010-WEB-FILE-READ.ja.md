# ADR-0010: Pythonを使わないWebファイル全体読取

## 状態

Python不在の実SSH受入と回帰を経て、2026-10-30に採用しました。

## 背景

全体読取はPythonでルート正規化・容量検査・内容符号化・更新日時取得を行います。公開内容はbase64で、任意のバイトを表現できます。先頭末尾・一覧・hash・書込はそれぞれ異なる契約です。

## 決定

環境を初期化した固定BashとGNU互換コマンド、Linuxの記述子パスを使用します。既存ルート境界を検査し、通常ファイル以外と観測容量超過を拒否し、確認した記述子から上限+1バイトまで読み、版付き応答をホストで検証します。statの時刻変換を再利用します。既存汎用SSH受信を維持し、上限はストリームではなく固定コマンド側であることを明示します。サイト設定・sudo・リモートhelperは追加しません。

## 代替案

Python維持では依存が残ります。専用リモートhelperは導入前提を増やします。シェルでのJSON生成はバイト・パスの処理を複雑にするため、任意内容と特殊な名前を保持できるbase64構造を使用します。

## 範囲と安全性

サイト・内容種別・SSH経路の権限を維持します。コマンド不足時は自動導入・代替・再試行をしません。リモート書込はありません。記述子確認によって正規化とopenが原子的になるわけではなく、同時書込で内容が変化する場合があります。hashの保証を主張しません。この段階では全体読取だけを移行します。

## 検証と運用

空・任意バイト・容量境界、不在・リンク・特殊名・日時、コマンド不足、不正応答、タイムアウト・取消を確認します。Python不在Linuxの非root実SSHで副作用監査と陽性対照を行います。provider/MCP回帰、英日シナリオ・結果更新、publishと実機照合後にGit納品します。公開リリースには別の承諾が必要です。

実SSH27条件が合格し、実行24条件は監査違反0・合成ファイル状態不変、3条件は実行前拒否でした。別の増大模擬条件では64バイト上限で65バイトだけを読み、内容を破棄しました。回帰1113成功・失敗0・Unix専用3件スキップです。NuGet脆弱性情報を取得できず、オフラインのビルド検証を脆弱性監査成功とは扱いません。
