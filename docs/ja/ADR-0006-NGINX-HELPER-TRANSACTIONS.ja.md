# ADR-0006: nginx専用helperのトランザクション

## 状態

実装方針として採用します。導入には規定のhelperポリシーと回帰・隔離Linux受入の成功が必要です。本番サーバーのsudoersやnginx設定の変更を承認する文書ではありません。

## 背景

nginx内部操作6件が特権shell/Pythonテンプレートを使用していました。設定更新と既定サイトのリンク解除には一体の復旧が必要です。SSH応答が失われると更新の成否を確定できず、既存の結果の真偽値だけでは不明と無変更を区別できません。

## 決定

固定されたnginx helper protocol 1の計画・確認・適用・状態照合・確定・復元へ置き換えます。設定読取/ログproviderと別コマンドの`nginx -t`を維持します。Application側は意図・プロファイル/経路の許可・確認・設定検証を担当し、独立helperは呼出UID・サーバーポリシー・正規化パス・効果の前提を検証します。

変更前にroot所有の記録、元のハッシュとinodeを永続化します。Linux x64で信頼したディレクトリのdescriptor相対操作と追跡しないファイルopenを使います。ファイルと既定サイトのリンクをまとめて復旧し、汎用interpreterやサービス実行窓口にしません。プロセス共有の非待機ロックで状態操作を直列化し、内容と期待状態を不変の意図ダイジェストへ結び付けます。

実在の隣接バックアップ`.kelpiebakup`を維持します。新記録は元の不在を明示し、設定内容をsentinelとして解釈しません。無関係/旧形式のバックアップを拒否し、旧バックアップや旧サイト記録を自動移行しません。運用者の明示照合用に残します。

設定書込・バックアップ操作・nginx PHP有効化の結果へ`OutcomeKnown`を追加します。既存フィールドとコンストラクターは維持します。falseの場合は効果の値が不完全なため、再試行前に照合が必要です。不明な変更には上限付き状態照会を1回行い、変更自体を自動反復しません。確定/復元の完了が照合できれば、応答喪失を成功として解消できます。

## 代替案

- 制約付きPythonを維持: 特権境界に汎用interpreterが残るため不採用です。
- Web helperへ任意コマンドを送る: サイト権限でnginx設定やshell実行を暗黙に許可するため不採用です。
- タイムアウトを変更なしの通常失敗にする: 復旧情報を失い、重複変更を招くため不採用です。

## 安全性と運用

helperポリシーはプロファイル検出やWebPublicSitesと独立し、呼出者/対象の初期許可は空です。ポリシー・バイナリ・状態領域・パスの祖先はroot所有かつgroup/others書込不可、状態領域は非公開にします。呼出UIDは要求値ではなく、特権起動の非0の`SUDO_UID`から取得します。明示設定した利用者だけへnginx設定管理権限を与えます。

初期対応はLinux x64だけとし、他環境はファイル操作前に失敗します。入出力上限・厳密なJSON・固定エラーを用い、機能一覧を許可には使いません。完了記録は重複抑止用に残し、状態領域を256件に制限します。保持/掃除は運用者が管理し、容量確保のためのバックアップ自動削除や権限拡大は行いません。

更新後の再読込/再起動は自動で行いません。設定検証は別の許可操作で、呼出側が成功後に確定します。利用者が許可されたhelperをOS上で直接呼べる場合、その利用者は明示設定されたnginx管理権限を持っています。helperがアプリの確認画面自体を認証するわけではありません。

## 実装・試験・文書

helper契約、Linuxファイル操作、provider変換、安全な復旧表示を同時実装します。実効果、競合編集、同内容のinode置換、ポリシー変更、symlink、再起動照合、不正応答、サイズ境界を検証します。偽操作の試験だけで使い捨てLinux/SSH/nginx受入を代替しません。導入・ポリシー・契約・`OutcomeKnown`・旧バックアップ・更新互換を英日で説明し、コマンドのシナリオ/結果を更新します。
