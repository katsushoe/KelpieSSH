# Web書込検査の契約

## 動作

通常/秘密ファイルの書込検査は、既存のサイト・パス・内容種別・実行モード・確認・helper分岐を維持します。接続先Bash/GNUでルートと親を解決し、親または存在する対象の領域外参照を拒否します。本文を開く、親を作る、試験ファイルを書く処理は行いません。領域内の通常ファイルリンクは検査で追跡しますが、別の原子的書込処理は対象リンクを引き続き拒否します。

既存通常ファイルはSSHユーザーの書込可能性、対象不在では既存親の書込可能性を判定します。親が不在ならCreateDirectoriesに従い、探索できない祖先がある場合の旧処理の楽観的な結果も維持します。書込可能なファイルでも親に置換権限がなければ実書込は失敗し得ます。canWriteは事前見込みであり、ACL・探索・置換の成功保証ではありません。SSHの実ユーザーと実効ユーザーは一致する前提です。検証対象Linuxでは適用されるグループ/POSIX ACLも判定します。

## 必要条件と上限

BashとGNU互換base64・realpath・dirnameが必要です。Python・sudo・追加helperは検査には不要です。コマンド探索先とロケールを固定し、プロファイル環境変数の上書きは無視します。内容の標準入力は送りません。内部応答は標準出力32768バイト、標準エラー2048バイト、解決済みUTF-8パス12288バイト以下です。不正・矛盾・過大・非対応パス応答は本文を返さず失敗します。既存10秒の期限・取消・ポリシー判定は維持します。コマンド不足や解決不能は安全なエラーです。文字列によるパス判定であり、悪意ある同時置換に対する完全な隔離は保証しません。

公開入力・設定・応答キーは変更しません。既存の理由・ReasonCode・案内・helper能力・秘密メタデータはアプリケーションで変換します。原子的書込とhashは変更しません。

## 受入

Debian12のBash/GNU環境で、非rootの通常/秘密SSH27条件、旧CPython3.12.16のJSON/失敗比較27条件、エラー/通信の補足5条件が全合格しました。本文ハッシュ・所有者・モード・ACLは不変、読取専用監査の違反は0です。Windows回帰1215件成功・Unix専用3件スキップ、ビルド警告/エラー0でした。helper分岐は回帰で確認し、新規の特権helperは導入していません。通常/秘密経路、所有者/グループ/ACL、探索不能の親、親不在と作成設定、リンク、不正応答、helper分岐を非rootの旧処理と比較します。本文読取・書込・外向き通信がないことを監査します。対応範囲は実測したユーティリティ/OSに限定します。[設計判断](ADR-0014-WEB-WRITE-CHECK.ja.md)を参照してください。
