# nginx設定の読取

nginx providerは、許可済みの主設定または許可されたincludeディレクトリ直下のファイルを読み取ります。`service_config_file_read`は`ServiceConfigFileReadResult`を返し、`service_config_file_check_read`は本文を返さず読取可否を確認します。探索は`nginx -V`と主設定の読取でincludeを取得します。固定内部コマンドの前に、既存のプロファイル・ポリシー・許可パス評価を行います。

固定読取は`/usr/bin/env`、`/bin/sh`、`/bin/bash`と、互換のある`base64`、`realpath`、`dirname`、`head`を使い、`/proc/self/fd`も必要です。継承環境を初期化し、Python、sudo、helper、追加パッケージ導入を要求しません。必要操作がない環境では読取エラーを返し、interpreterへの代替や自動導入はしません。他OS・他実装の互換性は個別の検証が必要です。

パスを正規化し、providerが許可した完全一致パスとinclude直下ディレクトリに照合します。通常ファイルを一度開き、そのファイル記述子を検査してから読みます。パス差し替えの競合を減らしますが、特権管理者による対象変更に対する原子的な保証は主張しません。

公開読取は最大65536バイトです。読取可否確認は1バイト上限で、本文を返しません。内部読取の正の上限は999999バイト、通信上限はstdout 1333340バイト、stderr 2048バイトです。追加の1バイトで切詰めを判定します。NUL、不正UTF-8、不正または過大な通信データ、切詰め位置で不完全になった多バイト文字は、取得内容を公開せずエラーにします。正常な切詰めでは既存のフラグと警告を返します。主設定探索の読取が失敗した場合、同じ主設定を後続の読取・可否確認で再試行しません。

この読取処理はリモート書込、一時ファイル、特権操作、設定変更、runtime切替、通信結果が不明な場合の自動再試行を行いません。取消・通信エラーは既存のコマンドサービスのエラー経路に従います。固定コマンドとホスト側変換は通常のSSHポリシーを通ります。公開結果の項目とプロファイル設定は変更しません。

設計と制約は[ADR-0008](ADR-0008-NGINX-CONFIG-READ.ja.md)を参照してください。Linux SSH受入は導入前の別の検証条件です。
