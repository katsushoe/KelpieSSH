# MCPサーバーのトレイ・設定・自動更新

Windows版にはKelpieMCPServerの管理アプリKelpieMCPTrayを同梱します。サーバー本体は従来どおりWindowsサービスや画面なしで動作します。サービスはユーザーの画面を表示できないため、起動時更新はログオン中のトレイ起動時に行います。

## 起動と操作

1. KelpieSSHを導入したWindows PCで、通常のWindowsユーザーとしてPowerShellを開き、`kelpiemcp tray`を実行します。設定画面を直接開く場合は`kelpiemcp settings`です。`kelpiemcp start`やサーバー本体を対話的に起動した場合も、同梱トレイを起動します。自動表示を抑止する場合は`--no-tray`を指定します。
2. Windowsタスクバー右端の通知領域にあるKelpieMCPServerアイコンを確認します。見つからない場合は隠れたアイコンの一覧を開きます。アイコンをダブルクリックするか、右クリックして「設定」を選びます。
3. 「Windowsへのログオン時にトレイを起動する」「トレイ起動時にMCPサーバーを起動する」「トレイ起動時に更新を確認して自動適用する」を選び、「保存」を押します。設定画面を閉じてもトレイは常駐します。「トレイを終了」はサーバーを停止しません。
4. サービスの開始・停止に通常ユーザーの権限が足りない場合は、右クリックの「管理者権限で操作」から対象操作を選び、Windowsのユーザーアカウント制御で確認します。「状態を確認」で結果を確認し、失敗した場合はログを確認します。

## 設定

秘密情報を含まない設定を`%LOCALAPPDATA%/Akatsukisoft/KelpieSSH/<installation-id>/tray.json`へ原子的に保存します。導入先ごとに保存先を分離します。管理ログと前回の更新結果もこのフォルダーへ保存します。既存サーバーのログ保存先は変更しません。

| 項目 | 必須 | 初期値 | 意味 |
| --- | --- | --- | --- |
| AutoStartServer | いいえ | true | トレイ起動時にサーバーを起動します。 |
| CheckUpdatesOnStartup | いいえ | true | 起動時に更新を確認し、検証済みの新しいMSIを自動適用します。 |
| StartAtLogon | いいえ | false | 保存時に、この導入先だけを現在ユーザーのログオン起動へ登録します。 |
| ReleaseApiUrl | いいえ | https://api.github.com/repos/katsushoe/KelpieSSH/releases/latest | 信頼する公開の更新APIです。 |

この設定はサーバーの信頼済みkelpiemcp.jsonとは別です。SSHプロファイル、秘密値、モード、許可パス、鍵、信頼基準を変更・自動承認しません。MSI削除時はこの導入先が所有するログオン登録を解除し、利用者設定は保持します。更新時は登録を保持します。トレイには既存のサーバー用ランタイムに加え、Windows x64版.NET Desktop Runtime 8が必要です。

同じWindowsユーザーの同じデスクトップセッションでは、トレイは1つだけ起動します。別の配置先から設定の起動を依頼しても、実行中のトレイの設定画面を表示します。

## 更新の仕様

ユーザー指定に従いGitHub ReleasesのMSIを使用します。公開済みの安定版で、4要素の数値タグが導入済みkelpie.exeより新しく、`KelpieSSH-<version>-x64.msi`が1件だけ存在することを検証します。正のサイズ（最大512 MiB）とSHA-256が必須です。メタデータは最大1 MiB、資格情報を埋め込まないHTTPSだけを使用します。GitHub APIでは同じリポジトリの配布URLだけを受け付けます。独自APIは同じ形式に対応する信頼済みの利用者設定として扱い、非公開配信元の認証は未対応です。

専用キャッシュへ取得し、サイズとSHA-256を照合します。導入先外へコピーした更新処理から管理者権限の処理を起動し、トレイを終了、正規CLIでサーバーを停止してMSIを適用します。MSIを読取りロックした状態で再検証し、終了0または3010を成功として扱います。PCを自動再起動しません。通常ユーザー側の処理がトレイを再開し、その1回は更新を再試行しません。

配信元へ到達できない場合や取得に失敗した場合も通常のサーバー起動を続けます。結果が確定した導入失敗では元のサーバーの復帰を試みます。インストーラーの時間切れなどで結果が不明な場合は、サーバー再起動や導入再送を自動で行いません。管理ログとWindows Installerの完了状態を確認してから再開します。更新時にWindowsの管理者確認が表示される場合があります。公開ファイルのアップロードやRelease公開は行いません。

設計は[ADR-0016](ADR-0016-MCP-TRAY-UPDATE.ja.md)、配信形式は[GitHubの公式仕様](https://docs.github.com/en/rest/releases/assets)、MSI処理は[WiXの公式仕様](https://docs.firegiant.com/wix/schema/wxs/customaction/)を参照してください。

通知領域のアイコンを右クリックして「バージョン情報」を選ぶと、管理トレイ、インストール済みMCPサーバー、配布版のバージョンと、開発元・ライセンスが表示されます。
