# 貢献手順

KelpieSSHは[OSS公開範囲](OSS_SCOPE.ja.md)に関するIssue・Pull Requestを受け付けます。[英語版](../../CONTRIBUTING.md)も参照してください。

## 作業を始める前に

既存のIssue・PRを確認してください。小さな文書修正、限定した不具合修正、テストは直接PRを提出できます。新コマンド・provider・ポリシー・互換性の変更は実装前にIssueで範囲を相談してください。脆弱性は[セキュリティ方針](SECURITY.ja.md)に従い非公開で報告し、公開Issueへ攻撃手順や秘密情報を書かないでください。

ホスト名・ユーザー・データには合成値を使います。本番プロファイル、秘密鍵、パスワード、トークン、未加工ログを含めないでください。期待する動作、実際の動作、製品版、OS、最小再現例を記載してください。

## 開発環境

各プロジェクトのnet8.0を扱える.NET SDKと、スクリプト実行用PowerShellを使用します。CLI/MCPの初期ホスト対象はWindowsです。provider結合試験には破棄可能なLinux SSH環境を使い、コンテナを使う試験にだけDockerが必要です。

復元には[パッケージ仕様](PACKAGES.ja.md)に記載された外部Moyai.ProviderAuthenticationが必要です。提供元から入手して公開ハッシュを照合してください。nuget.orgにあるとは仮定しません。フィード資格情報をcommitせず、依存をソースコピーへ置き換えないでください。

リポジトリルートで実行します。

```powershell
dotnet restore KelpieSSH.sln
dotnet build KelpieSSH.sln -c Release --no-restore
dotnet test KelpieSSH.sln -c Release --no-build --no-restore
```

提供パッケージが別ディレクトリにある場合は、先にパッケージ仕様の追加ソース付きrestore手順を使います。OS専用のスキップやSSH前提不足は区別して報告し、本番ホストで結合試験を実行しないでください。

## 変更の提出

提出先はdevelopとし、PRごとに一つの目的へ絞ります。問題、変更後の動作、関連Issue、検証結果を記載してください。管理者が範囲・互換性・安全性・試験根拠を確認してマージします。提出だけで採用や回答期限が保証されることはありません。

ソリューションのapplication/domain/infrastructure依存方向を維持します。モード・確認・信頼・パス・期限・秘密情報の境界を守り、接続先の動作を追加する場合は、必要に応じて破棄可能環境で成功・失敗・ポリシー拒否を検証してください。

英日文書は同時に更新します。コマンド・tool・設定変更では入力、設定、出力、状態遷移、エラー、試験を整理し、該当公開リファレンスとサンプルへ反映します。内部メモや実環境データを公開差分へ含めないでください。
