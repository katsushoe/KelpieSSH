# Webファイルの先頭・末尾読取

`web_file_head`と`web_file_tail`は既存のサイト・内容種別・パス・MCP権限検査を使用します。公開引数・応答項目・警告を維持します。`maxBytes`は1～1048576で、サイトの`MaxReadBytes`を上限に縮小します。`maxLines`は0～1000で、0では行数を制限しません。

環境を初期化した固定BashとGNU互換の`base64`・`realpath`・`stat`、先頭用の`head`またはバイト数・開始位置を指定できるGNU `dd`を使用します。`/usr/bin/env`・`/bin/sh`・`/bin/bash`・Linuxの`/proc/self/fd`も必要です。Python・sudo・リモートhelperは不要です。コマンド不足・非互換時は自動導入・代替インタープリター・再試行をせず失敗します。

headは先頭から有効バイト上限まで読みます。tailはopen前の観測サイズから`max(0, 観測サイズ - 有効maxBytes)`を開始位置にし、有効上限まで読みます。同時増大後の新しい末尾へ切り替えません。上限より大きいファイルも対象にできます。パス正規化・ルート内リンク・対象不在・通常ファイルの要件は[全体読取契約](WEB_FILE_READ.ja.md)に従います。開いた記述子を確認し、同じ記述子から更新日時を取得します。同時書込中の原子的な状態取得やhash固有の保証は提供しません。

バイト取得後、ホストで従来のPython `bytes.splitlines(keepends=True)`と同じ処理を行います。CR・LF・CRLFを行境界とし、区切りも保持します。headは先頭N行、tailは末尾N行を返し、末尾の区切りの後に空行を追加しません。NUL・垂直タブ・改ページ・不正UTF-8を含む他のバイトは保持します。バイト境界で多バイト文字やCRLFが分断される場合があります。`encoding: utf-8`の表記は内容の文字コード検証を意味しません。返却サイズは選択後のバイト数です。

コマンドのタイムアウトは10秒、SSH受信は標準出力2097152・標準エラー2048・標準入力0バイトに制限します。版付き応答は全体読取の構造と時刻変換を再利用し、行選択前に不正・非正規base64・容量超過を拒否します。通信容量超過・不正メタデータでは内容なしのエラーを返し、取消は既存動作を維持します。部分読取の上限警告とサイト上限への縮小警告も維持します。

一覧・hash・書込は変更しません。[ADR-0011](ADR-0011-WEB-FILE-SLICE.ja.md)を参照してください。
