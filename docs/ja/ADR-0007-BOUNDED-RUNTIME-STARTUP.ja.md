# ADR-0007: 任意runtime起動の容量制限

## 状態

2026-10-27、D1のライブラリ基盤として採用しました。PHP/Node診断アダプターと公開ツール登録は後続です。

## 背景

任意runtime診断には、信頼済み実行候補、環境を初期化する起動、全文蓄積前のバイト上限が必要です。SSH.NET 2026.0.0のSshCommandは拡張するPipeStreamを内部に持つため、Resultの取得後検査や並行読取だけで固定メモリー上限を保証できません。既存SSH要求の通信・応答契約も維持する必要があります。

## 決定

固定コマンド定義と要求へ任意のExecutionLimitsを追加し、位置指定コンストラクターは維持します。指定した要求だけ、非PTYのSSH.NET Shellと、利用側が所有する固定容量のstdout/stderr受信先を使います。チャネルごとに無作為な完了フレームで終了コードを受け、欠落・不正は成功と推測せず失敗にします。この経路ではSshCommandのResult・Errorを使いません。上限未指定の従来経路は維持します。

stdoutは要求した本文上限に完了フレーム用96バイトを加えた固定配列で、拡張しません。フレームを除いた本文もバイト数で検査します。stderrは独立した上限です。超過時は取得データを返さず、秘密を含まないSshCommandOutputLimitExceptionを返します。文字列入力は容量検査後にBase64のデータとしてシェル入力へ組み込み、コードとして評価しません。この経路のバイナリ入力は未対応です。UTF-8は厳格に検査します。取消時は専用チャネルを閉じますが、任意のリモート子プロセス終了まで保証するものではありません。

固定シェル入力は明示的なexitで終わります。全バイト送信後は専用の入力終端例外を返し、SSH.NETの入力リスナーをチャネル破棄前に終了させます。エラー通知ではこのローカルな終端だけを正常処理し、上流の0バイト送信と終了の競合を避けます。リモート完了フレームの欠落を許可する変更ではありません。

固定起動用にIgnoreEnvironmentOverridesを追加します。runtime検出はさらにenv -i、プロジェクト外の作業場所、固定OSコマンド、root所有で書込不可の成分、上限付きリンク解決、直前の属性再検証を使います。GNU timeoutで5秒後にruntimeプロセスグループを停止します。PHP/Nodeの固定選択子だけを受け付けます。D1では既定カタログへ追加しません。

## 代替案

- 全文取得後の長さ検査・SshCommandの並行読取：ライブラリ内部の受信量を制限できません。
- SSH.NETの非公開フィールド操作・独自fork：未公開内部構造への依存と保守範囲が増えます。
- OpenSSHの別プロセス：資格情報・ホスト鍵・password sessionを別途連携する必要があります。
- 非PTY Shellと固定容量受信先：既存ライブラリの公開APIと既存の認証・ホスト鍵検証を使えます。上限指定要求だけに採用します。

## セキュリティと運用条件

OS・SSHログイン環境と、固定起動基盤の/bin/sh、env、stat、readlink、timeout、base64を信頼する前提です。既に起動した不正なログインシェル・ローダーの処理は取り消せません。リンクは成分ごとに検査し、先に正規化して書込可能な中間ディレクトリを見落とすことを避けます。展開は長さと回数を制限したASCIIのシステムパスだけです。特権管理者の置換は信頼済みOSの境界内であり、属性比較は実行ファイルをカーネルの記述子へ固定する保証ではありません。

非PTYシェルを許可するサーバーが必要です。起動表示、強制コマンド、チャネル異常でフレームが成立しない場合があります。失敗後に上限なし通信へ切り替えません。runtime検出は通常のSSHコマンドサービスを通し、そこで直接rootログインを拒否します。プロファイルの信頼解決と結果変換は既存呼出側・後続D2の責務で、D1は新しい権限根拠ではありません。

## 実装と検証

Applicationに上限契約と固定起動資産、Infrastructureに認証・直接受信・フレーム・チャネル管理を置きます。既存MCP/CLIの応答型は変えません。単体では容量、UTF-8境界、フレーム、データ入力、権限経由の転送、既定カタログ未登録を検査します。隔離実SSHでは大量出力、取消、期限、起動フック、危険な候補・リンクを確認します。D1起動の成功を、runtime機能やB3全条件の実装完了とは扱いません。

## D2の採用判断（2026-10-27）

D1起動処理とPHP/Node別の固定catalogを使い、型付きruntime.infoをCLI/MCPへ対称に公開します。固定ホスト鍵・非root・毎回の権限評価・上限付き厳格JSON・要求/runtime一致を必須とします。Nodeは固定の組込みfs/cryptoのみを読み込みます。D2では識別情報に依存する準備/結果キャッシュを導入せず、毎回再検証します。refreshは受け付け、cachedは常に偽です。広域inventoryの拡張は既存の意味を変更し、汎用interpreter公開は固定操作の境界に反するため採用しません。[公開契約](RUNTIME_INFO.ja.md)に対応し、単体・公開schema・隔離runtime/SSHの試験後に納品します。全条件のD3受入とは区別します。
