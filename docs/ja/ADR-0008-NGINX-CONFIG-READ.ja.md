# ADR-0008: Pythonを使わないnginx設定読取

## 状態

2026-10-28に実装しました。使い捨てLinux/SSH受入と全体回帰は合格し、導入確認は別途管理します。

## 背景

既存の固定nginx設定読取は、許可パス照合、通常ファイル判定、上限付きUTF-8取得にPythonを必要とします。探索、読取・可否確認、変更前確認から利用されます。SSH応答は保持前に権限と容量を制限し、正規化とopenの間のパス変更も考慮します。

## 決定

継承環境を消した固定の非特権shell処理とGNU互換の標準ツールを使います。既存の許可完全一致ファイル/直下ディレクトリと照合し、通常ファイルを一度開き、記述子のパスを検査して上限と追加1バイトを読みます。バイト列は上限付きbase64としてホストへ送り厳密に検証し、公開結果の型を維持します。主設定探索の失敗後に同じ主設定を自動再試行しません。不正応答のエラーには例外や取得内容を含めません。通常のコマンドポリシーと既存の取消動作を使用します。

既存内部上限999999バイトと追加1バイトをbase64へ変換しても範囲を狭めないため、選択式SSH stdout上限の許容最大を1048576から2097152バイトへ広げます。この読取はstdout 1333340・stderr 2048バイトを指定し、他の既存上限は変更しません。

## 代替案

Pythonを維持すると依存が残ります。未検証のテキストを直接転送する方法では、バイナリと厳密UTF-8の上限検査を満たせません。特権helperは読取専用操作に導入・権限の追加を求めます。汎用interpreter実行は許可された操作の境界外です。いずれもこの読取には採用しません。

## 対象・安全・運用

対象はnginx主設定/include読取と、その内容を検査する操作です。nginxログ、Webファイル、特権helperは置換しません。`/bin/bash`、互換のある`base64`、`realpath`、`dirname`、`head`、`/usr/bin/env`、`/bin/sh`、`/proc/self/fd`を必要とし、不足時は自動導入やinterpreter切替をせず失敗します。記述子検査はパス差し替えの競合を減らしますが、特権側の変更に対する原子的な保証ではありません。この読取はリモートファイルを作成・変更しません。

## 実装と検証

Applicationが固定テンプレート、バイト応答検証と結果変換を担当し、Infrastructureは既存の上限付きSSH受信を担当します。英日MCP仕様、シナリオ、結果記録を更新します。16条件の使い捨てLinux/SSH計画でパス、内容境界、ツール不在、権限、通信障害、副作用を確認します。Windows MSYSと単体試験は補助証跡であり、Linux/SSH受入の代替ではありません。このADRだけでリリースしません。
